# Backroom Phase 3 (Emoji & Reactions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every standard Unicode emoji works by its `:shortcode:` (aliases and skin tones included) in messages, an emoji picker, composer autocomplete and reactions, all drawn with Twemoji art served from Backroom's own origin; members can react to messages in real time; admins (or everyone, if the owner allows it) can add custom emoji one at a time or by importing a zip in the browser.

**Architecture:** A new `packages/emoji` generates a compact shortcode table from `emoji-datasource` at build time and copies only the needed Twemoji SVGs into the SPA's static assets. Both the Worker and the SPA use its lookup/parse helpers. Reactions go over the existing WebSocket. A `react` frame is validated by the hub, written to D1 inside the channel's existing `enqueue` chain, and fanned out as a `reaction` frame. History, thread and catch-up payloads carry reaction summaries as an optional `Message.reactions` field. Custom emoji are REST + R2: multipart upload, type taken from magic bytes, served by the Worker behind a membership check. Changes reach open tabs as a hub `emoji.update` frame. The SPA gets an emoji context (custom set, skin tone, frequently used), safe emoji rendering inside the Phase 2 tokenizer, a keyboard-accessible picker, reaction pills and a custom-emoji page with client-side zip import.

**Tech Stack:** Node 26, npm workspaces, TypeScript 6.0.3, Hono 4.13.18, zod 4.6.7, Wrangler 4.160.1 (Workers, Durable Objects, D1, **R2**, static assets), Vitest 4.1.12 + `@cloudflare/vitest-pool-workers` 0.23.0, React 19.3.1, Vite 8.3.8, `@testing-library/react` 16.3.3. New, verified on the npm registry 2026-11-12:

- `@discordapp/twemoji` 16.0.1 (code MIT, graphics CC-BY-4.0, published 2025-07-01): `dist/svg/*.svg`, 3,846 files (9.16 MB, the largest 47,772 B). It covers all 3,526 images the generated table references (checked; P3-R1).

## Global Constraints

- Carried from Phases 1–2:
  - IDs are 26-char ULIDs, validated on the wire with `/^[0-9A-Z]{26}$/`.
  - Timestamps are INTEGER epoch ms.
  - Every API error body is `{"error":{"code":string,"message":string}}`.
  - Every non-GET request needs `Origin` = `APP_ORIGIN`.
  - Never log message bodies, full emails or tokens.
  - Exact dependency versions only.
  - No FOREIGN KEYs (R1).
  - `compatibility_date` stays `2026-08-22` (R6).
  - `apps/web` never uses `dangerouslySetInnerHTML`. Text renders as React text nodes.
  - A thing the caller may not see is `404 not_found` over REST and `nack not_found` over WS, identical to "does not exist".
- **Wire compatibility (tabs stay open across deploys):**
  - Only add optional fields or new frame types, to both the client and the server unions.
  - `parseClientFrame` keeps dropping unknown types.
  - `MessageSchema` and `Bootstrap` gain only optional members: `reactions?`, `customEmoji?`, `workspace.settings?`.
  - The web reducer handles every `HubFrame` type (exhaustive switch, no `default`).
  - An old tab must parse new payloads, and a new tab must parse old ones (Task 2 tests).
- **Emoji data:**
  - Generated by `packages/emoji/scripts/generate.mjs` from `emoji-datasource`, never hand-written.
  - Output goes to `packages/emoji/src/generated/` (git-ignored). It is regenerated by the root `postinstall` and by `pretest`/`predev`/`prebuild` hooks.
  - The generated `data.ts` is at most 400,000 bytes.
- **Shortcodes:**
  - Name characters `[a-z0-9_+-]`, at most 64 chars.
  - Skin tones are written `:name::skin-tone-N:` with N in 2–6. Tone 1 / none is the default yellow.
  - A tone applies to multi-person emoji uniformly: the variation `T` or `T-T`.
- **Reactions:**
  - The wire code matches `/^[a-z0-9_+-]{1,64}(::skin-tone-[2-6])?$/` (no colons around it).
  - Stored and broadcast in canonical form:
    - built-in: the primary `short_name`, with `::skin-tone-N` when toned;
    - custom: the emoji's name;
    - custom alias: its target's canonical form.
  - At most 50 distinct emoji per message (`MAX_DISTINCT_REACTIONS = 50`).
  - Reacting requires channel membership, like sending.
- **Custom emoji:**
  - Type from magic bytes only: PNG / GIF / JPEG.
  - Size ≤ 131,072 bytes (128 KB).
  - Dimensions ≥ 32×32 and ≤ 4,096×4,096. The upper bound is a plan choice against decompression bombs.
  - Name `^[a-z0-9_-]{1,32}$`, unique per workspace, and not equal to any built-in short name or alias.
  - At most 2,000 per workspace (`CUSTOM_EMOJI_LIMIT`).
  - R2 key `ws/<workspaceId>/emoji/<emojiId>`.
- **Who may add (`customEmojiPolicy`):** stored in `workspaces.settings_json` as `'admins'` (the default when absent) or `'everyone'`. Only the owner changes it. Delete is allowed for the creator, an admin or the owner. Deleting an emoji also deletes the aliases that point to it.
- **Image responses (`GET /emoji/:id`):**
  - `Content-Type` = the stored sniffed type
  - `X-Content-Type-Options: nosniff`
  - `Cache-Control: private, max-age=31536000, immutable`
  - `Content-Security-Policy: default-src 'none'; sandbox`
  - `ETag`; `If-None-Match` ⇒ `304`
  - Only for active members of the emoji's workspace.
- **Twemoji art:** served from our origin at `/twemoji/<img>.svg`, never from a CDN, copied into `apps/web/public/twemoji/` (git-ignored) before `vite build`/`dev`. The copy has 3,526 files and must be ≤ 19,000 files in total with each file ≤ 26,214,400 bytes (§13).
- **Attribution:** exact copy "Emoji graphics by Twemoji, CC-BY 4.0" on the About page (`/about`), with links to `https://github.com/jdecked/twemoji` and `https://creativecommons.org/licenses/by/4.0/`.
- `run_worker_first` becomes `["/auth/*", "/me", "/w/*", "/invites/*", "/health", "/channels/*", "/messages/*", "/emoji/*", "/ws"]`. Static Twemoji live under `/twemoji/` precisely so they never collide with `/emoji/*`.
- **Linear time:** shortcode scanning, like the Phase 2 tokenizer (Task 10 of Phase 2), is linear in body length. A 100,000-char body tokenizes in < 50 ms.
- **`localStorage`:** used only for per-user emoji preferences. Every access is wrapped in `try/catch`, and the UI works when storage throws.
- Zip import runs in the browser only. The server never unzips (§9, §13: 10 ms CPU).

## Review Focus

1. **Colon-heavy text:**
   - Input: times (`10:30:45`), `::::`, `:qq:rr:ss:`, a URL containing `:smile:`, `:<b>x</b>:`, and a 100,000-char run of `:zq`.
   - Expected: unknown codes stay text, a known code after an unknown one still renders, a code inside a URL stays part of the link, nothing becomes markup, and it stays fast.
   - Tests: Task 1 `findShortcodes resumes at the closing colon and is linear`; Task 8 `colon-heavy text renders inert and fast`.
2. **Same reaction through an alias or a skin tone.** Ann reacts `:thumbsup:` and Bob `:+1:` and the result is one pill with count 2. `:wave::skin-tone-3:` is a separate pill from `:wave:` (Task 4 test `aliases collapse into one reaction; tones stay distinct`).
3. **A custom emoji is deleted while a tab shows it in messages and reactions.** Every use turns into `:name:` text live, with no broken image (Task 10 test `deleting a custom emoji turns its uses into :name: text live`).
4. **Hostile upload:** an SVG or HTML file named `x.png` with `type: image/png`, a 1 KB PNG header claiming 20,000×20,000, a GIF labelled `image/jpeg`. The first two are rejected, and the GIF is stored and served as `image/gif` with `nosniff` (Task 5 test `type comes from magic bytes; disguised SVG/HTML and bombs are rejected`).
5. **A real workspace export zip:** `__MACOSX/` junk, nested folders, upper-case names, two files with the same name, a 5 MB entry, and names that already exist on the server. Import reports a result per file, never inflates the oversized entry, and continues past failures (Task 11 test `zip import reports per-file results and skips junk`).

  - `formatShortcode(name: string, tone: SkinTone | null): string` — `'wave::skin-tone-3'`; tone `null`/`1` ⇒ `name`. No outer colons.
  - `type ShortcodeMatch = { index: number; length: number; name: string; tone: SkinTone | null }`
  - `findShortcodes(text: string, isKnown: (name: string, tone: SkinTone | null) => boolean): ShortcodeMatch[]` — single left-to-right scan:
    - A candidate is `:` + 1–64 name chars + `:`, optionally followed immediately by `:skin-tone-N:`.
    - Known with tone ⇒ emit including the tone.
    - Else known without tone ⇒ emit the bare code, and resume at the tone's opening colon.
    - Else resume scanning **at the candidate's closing colon** (so `:foo:smile:` still finds `:smile:`).
    - Each character is examined at most twice.
  - `type EmojiMatch = { name: string /* the matched short name */; record: EmojiRecord }`
  - `searchEmoji(query: string, limit: number): EmojiMatch[]` — lower-cases and strips colons. Rank 0: a name starts with the query. Rank 1: a name contains `_q` or `-q`. Rank 2: `keywords` contains the query. Within a rank, results follow `order`. One entry per record (its best-ranked name). `hidden` records are excluded.
  - `emojiInCategory(c: EmojiCategory): EmojiRecord[]` — non-hidden, by `order`.
  - `twemojiSrc(img: string): string` = `` `/twemoji/${img}.svg` ``.
  - `DEFAULT_FREQUENT = ['+1','heart','joy','tada','eyes','pray','white_check_mark','fire']`.
  - `scripts/generate.mjs` writes `src/generated/data.ts` (`export const DATA: EmojiRecord[] = JSON.parse(<one string literal>)`, records sorted by category index then `sort_order`) and `src/generated/images.txt` (every `img` incl. skins, one per line, sorted, unique).
    - `char` = `String.fromCodePoint(...unified.split('-').map(h => parseInt(h, 16)))`.
    - `img` resolves each `unified` against `@discordapp/twemoji/dist/svg`. Codepoints are lower-case hex with no leading zeros, and the first existing candidate wins: (1) drop every `fe0f` unless the sequence contains `200d`; (2) drop every `fe0f`; (3) keep all.
    - Skin tone N uses `skin_variations[T] ?? skin_variations[`${T}-${T}`]` with `T = 1F3FB…1F3FF`.
    - `hidden` when `category === 'Component'` or `obsoleted_by` is set.
    - The script exits non-zero on any missing image or tone.
  - `scripts/copy-twemoji.mjs <dest>` (also `export async function copyTwemoji(dest: string): Promise<{ count: number; bytes: number }>`) — empties `dest`, copies exactly the files in `images.txt`, throws if `count > 19_000` or any file exceeds 26,214,400 bytes, prints `copied <count> twemoji (<bytes> bytes)`.

       - Otherwise ⇒ `null`.
